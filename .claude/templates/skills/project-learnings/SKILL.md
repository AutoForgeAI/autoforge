# Project Learnings

This skill is a living document maintained by the coding agents working on
this project. It captures knowledge that is specific to THIS codebase and
that would save a future session time or prevent a repeated mistake.

**Read it before starting work. Update it after finishing a feature.**

## How to update this skill

After marking a feature as passing, ask yourself: *"What did I learn in this
session that the next agent would want to know?"* If the answer is nothing
new, leave this file alone. Otherwise, edit the relevant section below.

Rules:
- Keep entries short: one bullet, one fact, written as an instruction.
- Be concrete: name files, commands, components, and error messages.
- Merge or rewrite existing bullets instead of appending duplicates.
- Delete bullets that turned out to be wrong or are no longer true.
- Do not record feature status or progress (the feature database tracks that).
- Do not record secrets, tokens, or credentials.
- Keep this file under ~200 lines; prune the least useful entries first.
